# BACKEND-PLAN: DigitalVine Multi-Tenant SaaS

## Контекст

Текущий проект — личное Mini App Светланы Лоза с одним специалистом и хардкодом.
Задача: превратить его в платформу, где любой специалист запускает своё приложение через центральный бот, без помощи разработчика. Специалист получает брендированный бот + Mini App за ~15 минут.

**Принятые решения:**
- Онбординг: через центральный Telegram-бот
- Оплата: ЮKassa / Stripe
- White Label: цвет акцента + готовые темы + своё лого/название
- Заявки: в БД + пересылаются в бот специалиста

## Какие API нужны

Все — Vercel Serverless Functions в папке `tg-app/api/`.

| Метод + Путь | Назначение |
|---|---|
| `POST /api/platform-webhook` | Webhook центрального бота (онбординг специалистов) |
| `POST /api/specialist-webhook` | Webhook каждого бота специалиста (заявки от клиентов) |
| `GET /api/config?u=USERNAME` | Mini App загружает конфиг специалиста (тема, услуги, фото) |
| `POST /api/lead` | Mini App сохраняет заявку клиента |
| `POST /api/payment/callback` | ЮKassa/Stripe уведомляет об оплате |

Уровни доступа:
- `GET /api/config` — публичный, только чтение, секретов нет
- `POST /api/lead` — требует валидации `initData` от Telegram
- `POST /api/payment/callback` — требует проверки подписи от платёжки

## URL структура Mini App (мультитенант)

```
https://digitalvine-landing-xwru.vercel.app?u=@mariabot
```

- Параметр `?u=USERNAME` загружает конфиг нужного специалиста
- Если параметра нет — показывается демо (конфиг Светланы Лоза, как сейчас)
- Один деплой обслуживает всех специалистов

## Кто что видит и редактирует

| Роль | Доступ |
|---|---|
| **Клиент** | Видит Mini App специалиста: фото, имя, услуги, форму заявки. Не видит других специалистов. |
| **Специалист** | Через своего бота: управляет своим профилем, услугами, смотрит заявки. Не видит других специалистов. |
| **Платформа (Светлана)** | Центральный бот: видит всех специалистов, управляет подписками, может деактивировать аккаунт. |

## Онбординг специалиста (поток через центральный бот)

```
Специалист → /start в @digitalvine_platform_bot

Шаг 1: «Как тебя зовут? Введи имя и фамилию»
        → сохраняет display_name

Шаг 2: «Отправь своё фото» (или «Пропустить»)
        → загружает в Supabase Storage

Шаг 3: «Добавь свои услуги (до 5 бесплатно)»
        → интерактивное добавление кнопками

Шаг 4: «Вставь токен своего бота от @BotFather»
        → проверяет токен через getMe, сохраняет
        → автоматически устанавливает webhook специалиста

Шаг 5: Готово! Бот отправляет:
        «✅ Твоё приложение: [ссылка]
         Кнопку для клиентов можно добавить в своего бота.»
```

## Подписка и White Label (поток)

```
Специалист: /upgrade в боте

Бот: «Pro-план — 990 ₽/мес. Что открывается:
      ✅ Неограниченные услуги
      ✅ Выбор темы приложения
      ✅ Своё лого и название бренда»

→ кнопка «Оплатить» → ЮKassa checkout link

Оплата прошла → webhook /api/payment/callback
→ specialists.plan = 'pro', plan_expires_at = now + 30 дней
→ бот: «Оплата принята! Выбери тему:»
  [Dark Purple] [Ocean Blue] [Forest Green] [Warm Gold]

→ специалист выбирает тему
→ бот: «Хочешь добавить своё лого?» → загружает фото
→ бот: «Название бренда?» (или «Пропустить»)
→ сохраняется в specialists.theme (jsonb)
→ Mini App применяет тему при следующей загрузке
```

## Порядок разработки (фазы)

### Фаза 1 — Основа (MVP, 1–2 недели)
1. Настроить Supabase: создать таблицы, Storage bucket для фото
2. `GET /api/config` — возвращает JSON со специалистом
3. Обновить Mini App: принимает конфиг, рендерит динамически
4. `POST /api/lead` — сохраняет заявку + пересылает боту специалиста
5. Центральный бот: шаги 1–5 онбординга

### Фаза 2 — Монетизация (1 неделя)
6. Интеграция ЮKassa (тестовый режим)
7. `POST /api/payment/callback` — активация Pro
8. Лимит 5 услуг на Free

### Фаза 3 — White Label (1 неделя)
9. Готовые темы (4 набора CSS-переменных)
10. Загрузка лого → Supabase Storage
11. Применение темы в Mini App через `/api/config`

## Проверка работы (как тестировать)

1. Зарегистрировать тестового специалиста через центральный бот
2. Открыть `?u=@testbot` в браузере → должен показать его профиль
3. Заполнить форму → проверить запись в таблице `leads` и сообщение в боте специалиста
4. Оплатить тестовый платёж ЮKassa → проверить `specialists.plan = 'pro'`
5. Сменить тему → открыть Mini App → проверить CSS-переменные

## Что НЕ включать в MVP

- Веб-панель администратора (не нужна, всё через бот)
- Аналитика дашборд (только счётчик заявок в боте)
- Email-уведомления (Telegram достаточно)
- Мобильное приложение
- API для внешних интеграций
